## Decisiones tomadas en este issue
- La migración `supabase/migrations/20261118221000_storage_videos_series.sql` verifica `to_regclass('storage.buckets') IS NOT NULL AND to_regclass('storage.objects') IS NOT NULL` dentro de un bloque `DO $$` con `EXECUTE`, para ejecutarse en Supabase real sin romper los specs PGlite del repo que solo instancian el esquema `auth`. En `src/__tests__/storage-videos-series.spec.ts` se instancia el esquema `storage` completo con RLS y se validan las 3 políticas + ausencia de `UPDATE`.
- En `videos_series_select_alumno_o_entrenador` se valida con regex UUID el primer segmento de `storage.foldername(name)` antes de castear a `::uuid`, evitando errores `22P02` si existen objetos en otros buckets con rutas no-UUID.
- `src/lib/athlete/video-serie.ts` implementa generación UUID local con respaldo `crypto.getRandomValues` para no crear `src/lib/athlete/uuid.ts` (que pertenece a BE-00) y evitar conflictos al mergear.
- `video-subida.ts` marca las entradas con error 4xx como `estado: "error"` conservando el blob en `AlmacenVideos` (para que `reintentarVideoPendiente` pueda reintentar) mientras evita que los barridos automáticos reintenten errores 4xx hasta acción explícita del alumno.
- `attachVideoForSet` delega en `adjuntarVideoASerie(..., { tipo: "enlace", url })`, que actualiza `video_url` y `videoEstado: "listo"` sincrónicamente antes del primer `await` para mantener compatibilidad con los tests existentes que no hacen `await` sobre `attachVideoForSet`.
- `athlete-shell.tsx` exporta `activarYSincronizarAlAbrir` y `manejarReconexionOnline` y las invoca en `useEffect` para disparar `sincronizarVideosPendientes` al abrir con señal y al reconectar (`online`), manteniendo aislamiento estricto por usuario autenticado.
